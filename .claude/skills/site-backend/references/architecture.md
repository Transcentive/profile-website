# Architecture & conventions

## The big picture

```
                         ┌─────────────────────────── Ubuntu droplet (DigitalOcean) ───┐
   visitor ── HTTPS ──▶  │  Nginx (TLS, :443)                                            │
                         │   ├─ tomsherlock.space         → static files + proxy /api,/admin │
                         │   │                            to Go backend  (127.0.0.1:8080) │
                         │   ├─ brewery.tomsherlock.space → reverse-proxy 127.0.0.1:9001     │
                         │   └─ queue.tomsherlock.space   → reverse-proxy 127.0.0.1:9002     │
                         │                                                                │
                         │  Go backend (systemd)  ──▶  PostgreSQL (127.0.0.1:5432)        │
                         │  sub-app A (systemd)                                            │
                         │  sub-app B (systemd)                                            │
                         └────────────────────────────────────────────────────────────────┘
```

- **Nginx** terminates TLS and is the single front door. It serves the static
  frontend directly and reverse-proxies dynamic + subhosted traffic.
- **The Go backend owns the MAIN site's dynamic surface only** — the API the
  static frontend calls and the admin endpoints. It does NOT proxy sub-apps;
  that is Nginx's job (see [subhosting.md](subhosting.md)).
- **Sub-apps are independent services** on their own ports/subdomains, in any
  stack (the brewery app is Go + Flutter). They are wired in at the Nginx layer.

## Directory layout (`backend/`)

```
backend/
├── cmd/server/main.go        entrypoint: config → store → server, graceful shutdown
├── internal/
│   ├── config/               env-based Config + validation
│   ├── server/               chi router (server.go) + middleware.go
│   ├── handlers/             one file per concern: handlers/contact/content/analytics/admin
│   ├── store/                pgx pool + sqlc Queries wrapper
│   └── dbgen/                GENERATED by sqlc — do not edit by hand
├── db/
│   ├── migrations/           NNNN_name.up.sql / .down.sql (golang-migrate naming)
│   └── queries/              *.sql with `-- name: X :one|:many|:exec` for sqlc
├── deploy/
│   ├── nginx/                main-site.conf, subhost.conf (per-app), proxy.conf snippet
│   └── systemd/              site-backend.service unit
├── go.mod  sqlc.yaml  Makefile  .env.example  .gitignore
```

## Conventions

- **Routing** lives only in `internal/server/server.go`. Add a route there and a
  method on `*handlers.Handler`. Public reads/writes under `/api`, privileged
  ones under `/admin` (which is gated by `RequireAdmin`).
- **Handlers** are thin: decode + validate input, call `h.store.Queries.X`, write
  JSON via `writeJSON`/`writeError`. No SQL in handlers.
- **All DB access goes through sqlc-generated methods** on `h.store.Queries`. To
  add a query, edit `db/queries/*.sql` and run `make sqlc` — never hand-write
  files in `internal/dbgen/`. See [database.md](database.md).
- **Config** is environment-only (12-factor). Add a field to `config.Config` and
  document it in `.env.example`. `DATABASE_URL` and `ADMIN_TOKEN` are required.
- **Errors**: log the internal error with `h.logger`, return a generic message to
  the client. Never leak driver errors to responses.
- **Schema style**: prefer `TEXT NOT NULL DEFAULT ''` for optional strings so
  sqlc maps them to plain Go `string` (keeps handlers free of pgtype wrappers).
  Use `JSONB` for free-form content; timestamps are `TIMESTAMPTZ NOT NULL`.

## Capabilities and where they live

| Capability        | Routes / code                                            |
|-------------------|----------------------------------------------------------|
| Serve static site | Nginx `main-site.conf` (`root` + `try_files`)            |
| Contact/messaging | `POST /api/contact` → `handlers/contact.go`             |
| Content/CMS API   | `GET /api/content/{slug}`, `PUT /admin/content/{slug}`  |
| Admin + analytics | `/admin/*` (token), `handlers/admin.go` + `analytics.go`|
| Subhost mini-apps | Nginx per-app `subhost.conf` (see subhosting.md)        |
